# V2 architecture and constraints

V2 extends the existing components. `FlightTimers`, `GpsRecorder` and `Alerts` retain their recording/timing/hardware roles. Navigation still receives elapsed seconds and UTC only; GPS info stays confined to `GpsRecorder` and native FIT recording.

`NavlogApp.flightState()` derives NO_FLIGHT, PLAN_SELECTED, GROUND_ACTIVE, AIRBORNE_CHECKS_IDLE/RUNNING/COMPLETE, LANDED, FINISH_PENDING, FINISHED, RECORDING_ERROR and RECOVERY_REQUIRED. The authoritative inputs are existing started/finished, airborne-period and CLEAROFF data plus recording warnings. Persisted `finishRequested` tracks an incomplete completion operation; `discarded` is an empty current-log tombstone. UI screen, highlighted menu row and debounce timestamp are transient, not parallel flight states.

Plan data is separate in `FlightPlan`: two immutable demo IDs/revision 1, maximum four legs, names/endpoints/date/demo metadata. Original legs are retained; the outbound plan reuses its first two. Selected plan ID/revision and display metadata are stored in the existing schema-2 navigation dictionary. Old checkpoints without a plan ID restore the original route. Unknown IDs/revisions are rejected, preserving checkpoint fallback rather than binding an unrelated plan. New plan revisions must get immutable IDs and retain old catalogue entries while their checkpoints remain supported. No external transport/import is implemented.

CLEAROFF retains planned 10 NM segments and acknowledgement anchors. Running acknowledgement now writes its own scheduled/actual history pair; an already-due acknowledgement updates the queued due entry. The two-second elapsed guard prevents consuming a newly started interval. Undo keeps its previous check snapshot and history correction mechanism. A frequency change queues a radioChange event in the existing delivery queue; pending flags survive dismissal, unchanged later legs and recovery.

Commands keep stable IDs internally so recording/history regressions remain testable. `menuIds()` and `recoveryIds()` expose only contextual operations. Flight Timers is the first/wrap position of the same navigation ring; it has no selected action, so START there does nothing. Alert display order maps to existing stored mode IDs (Both=2, Vibration=0, Audible=1, Off=3).

Finish prepares developer fields and attempts native save. On failure, local end/leg/airborne closure is still recorded with pending completion, preserving the original end on retry. On native success, a local checkpoint must also succeed before completion/exit. Discard calls the known native handle only; false/exception preserves pending state. After native success, a newer empty checkpoint is written before removing the older current checkpoint, preventing fallback to discarded flight details. Three prior archives remain untouched. Native save/discard and local storage cannot be made atomic; interruption between them remains a review boundary.

No unknown native handle is automatically recreated on startup. Local checkpoints restore automatically, but native continuity cannot be inferred from `createSession` or a true save return after restart. A known same-instance session can retry; no-session recording creation can retry only when no prior native recording could exist. Unknown native state keeps the original data and blocks blind discard/new flight/exit. This intentionally limits automatic recovery rather than inventing an unsupported identity query.

Garmin's documented [Session.discard](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityRecording/Session.html#discard-instance_function) returns a success Boolean. A real simulator session start/discard passed in the complete suite; false-return failure handling uses injected tests. Actual physical discard and launcher exit remain acceptance items. [System.exit](https://developer.garmin.com/connect-iq/api-docs/Toybox/System.html#exit-instance_function) is the supported normal lifecycle exit; no activity-list-specific navigation is assumed.

[Garmin resources](https://developer.garmin.com/connect-iq/articles/core-topics/Resources.html) support bitmap transparency. The SVG's black rectangle was removed. A separate acceptance-only bitmap resource from the same SVG is rendered on two colours to verify compiled transparent corners without reusing the manifest launcher resource inside the app. This proves the asset, not physical launcher compositing.

V2 simulator GPS playback showed a -19.8 m altitude offset from synthetic input; earlier playback showed -122 m. The discrepancy varies between runs. No navigation calculation uses altitude, and no speculative correction is applied to FIT. Physical calibration/accuracy, reboot continuity, DND, battery and Garmin Connect custom-field presentation remain unverified. Existing dynamic dictionary warnings and bounded checkpoint/history storage remain.
